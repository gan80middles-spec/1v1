# AI 与导演算法校准（2026-10-03）

## 结论

校准版 `utility-v4` 已实现并可单独选择。固定 800 场脚本基线中的普攻空挥率由 **53.30% 降至 37.07%**，达到该评测口径的 `<45%` 目标；独立 400 场留出集为 **36.30%**。AI 自对战仍有 **54.66%** 的普攻空挥，不能据此宣称所有场景均低于 45%。

导演实验有改善，但尚未达到联合验收要求：留出集冷场 P90 缩短 **13.22%**，低于 20%，一边倒比例从 **6% 升到 10%**。生产继续推荐 **校准 AI + pacing off**。实验实现与数据保留供复现，未升级为生产默认策略。

原始审计见 [完成情况核查](./completion-audit-2026-10-03.md)。本轮不等于 MVP 全部验收通过，人工观感评审及其他审计缺口仍保留。

## 修正内容

1. **因果时序结算**：旧预测会扣除受伤风险，却仍给生效前被非致死硬直打断的攻击计入收益。新预测按 tick 批量结算接触，截断未释放的后续攻击，保留同 tick 互换、已经释放的投射物，以及首发后不可撤销的连续弹体。KO 后结束预测，不给终局以后的弹体计伤害。
2. **普攻必须有自身命中收益**：训练诊断样本的 61 次空挥中，34 次出手时已被预测为零伤害。由于普攻的切换门槛低于移动，它们仅凭位置改善被选中。新版本单独统计“本次新出手”的伤害收益；零收益普攻不进入选择池，已有弹体伤害不能替这次普攻背书。候选 trace 保留过滤原因。
3. **导演可观测性与实验**：评测记录提示数、受影响评分、同一次决策去掉导演后的选择差异，以及改变选择后 120 tick 内是否出现互动。后者只是后续观察，不宣称互动一定由导演造成。提前介入实验将冷场阈值 180→120 tick、渐入 30→15 tick；相对距离实验按剩余距离归一化进展。加分上限仍为 1.2，脱困合计上限 2.5、基础分及额外死亡风险限制不变。

新预测仍是 30 tick、三种运动假设的近似模型，没有变成完整战斗树；它没有在每次预测命中后重算击退轨迹和对方全部未来决策。因此仍会有几何误差、观察延迟和未承诺行动导致的落空。没有降低反应延迟、关闭误差、改变随机预算，或调整 HP、伤害、招式、充能与物理数值。

## 冻结数据与结果

使用原 `ai-baseline-v1` 的 400 训练 / 400 留出配置，以及原 `pacing-pairs-v1` 的 100 训练 / 100 留出配置。所有种子均纳入，没有筛掉失利或较差比赛。训练完成后，先写入 `artifacts/calibration/freeze.json` 冻结算法与采用决策，再运行留出；没有依据留出结果继续调参。冻结后的训练复跑与训练结果逐场输入一致。

### 脚本基线：只统计被测 AI 一方

| 指标 | 原版 v3 | 校准版 v4 |
|---|---:|---:|
| 全部 800 场普攻空挥率 | 53.30% | **37.07%** |
| 留出 400 场普攻空挥率 | 53.34% | **36.30%** |
| 训练 400 场普攻空挥率 | 53.25% | **37.83%** |
| 普攻出手 / 实际有效出手 | 7,205 / 3,365 | 5,794 / **3,646** |
| 全部胜 / 负 | 795 / 5 | **800 / 0** |
| 技能有效率 | 84.06% | 84.08% |
| 有效互动覆盖 | 56.66% | 57.15% |
| 首次互动 P90 | 0.667 秒 | 0.667 秒 |
| 非法请求 / 无效比赛 | 0 / 0 | 0 / 0 |

空挥减少并非只靠降低出手总量：有效普攻次数增加约 **8.35%**。留出集空挥率下降 17.04 个百分点；按种子聚类、将换边样本放在同一簇的 2,000 次配对 bootstrap，95% 区间为下降 **14.59～19.82 个百分点**。这些是当前固定评测的证据，不代表对任意未来策略的胜率承诺。

### 导演实验：同一新版 AI 上配对比较 off / pace

| 指标 | 训练 off | 训练实验 pace | 留出 off | 留出实验 pace |
|---|---:|---:|---:|---:|
| 场数 | 100 | 100 | 100 | 100 |
| 冷场 P90 | 5.083 秒 | 4.350 秒 | 4.917 秒 | 4.267 秒 |
| 冷场 P90 改善 | — | 14.43% | — | **13.22%** |
| 每场最长冷场的 P90 | 5.100 秒 | 4.500 秒 | 5.300 秒 | 4.517 秒 |
| 一边倒比例 | 6% | 7% | 6% | **10%** |
| 重复无效攻击 | 137 | 128 | 135 | **158** |
| 普攻空挥率 | 54.57% | 53.89% | 54.76% | 55.54% |

冷场仍采用原定义：完整有效互动间隔至少 180 tick，包含开场和终局截尾；改变的是导演触发时机，没有改变指标定义。留出集 P90 改善的配对 bootstrap 95% 区间约 **-2.58%～21.28%**，没有充分证据认定改善稳定达到 20%。原报告的 2.61% 来自旧 AI 的全量比较，不能与这里的新 AI 留出数字直接相减。

训练中，旧导演 134 次提示、2,554 次评分受影响、83 次选择变化；提前且相对距离归一化的实验为 250 次提示、5,437 次评分受影响、202 次选择变化。机制确实更容易影响行动，但更多干预没有同时保证更好的双边参与。**实验不晋升为推荐生产策略。**

## 正确性、接入与性能

- 类型检查、构建、**338 项测试**通过；模块边界检查 89 个源文件、5 个负例通过；原种子清单 hash 通过。
- 新版 200 配置重复运行、200 次输入重放一致；20 次完整状态恢复，26,078 个后续输入一致，末态 world/runner hash 一致。实测每决策候选最多 18、每假设积分段最多 12。
- 20 场四 worker 正式生产包，与单线程重跑的输入和最终 runnerHash 一致。
- off / observe / pace 的正式序列化包共 18 次恢复，7,560 个后续输入一致；网页三模式的导出 trace 经规范化 JSON 后与 Node 相同，旧版切换和移动窄屏检查通过。
- 浏览器初次测试直接比较内存对象和 JSON，遇到 JavaScript `-0` 经 JSON 变为 `0` 的差异；测试改为项目既定 canonical hash 比较后通过，没有因此修改算法或放宽其他字段比较。

性能在同一进程交替运行 v3 / v4，每版 10 场预热、100 场测量、每场严格 2,700 tick。仅性能夹具把 HP 设为 1,000，生产内容不变；关闭导演、trace、帧记录。
